# 定义历史记录与内容版本模型

Type: grilling
Status: resolved
Blocked by: 04, 05

## Question

如何定义会话、转写、反馈和内容版本之间的关系，使本地 SQLite 历史可回看、中断会话可识别，且旧记录不会因面试说明后续修改而失真？

## Answer

完整逻辑模型见 [历史记录模型](../../../docs/product/history-model.md)。

关键决策：

- 实时连接成功时立即创建“进行中”会话，每轮最终转写确认后立即、幂等地追加保存。
- 应用启动时将遗留的“进行中”会话收敛为“已中断”。
- 每场会话保存当时候选人画像与面试说明的完整不可变快照、人类可读版本标识和内容哈希。
- 反馈状态与会话结果分离。已完成会话的反馈可以生成失败并在历史页使用原转写和快照重试。
- 记录默认永久保留。删除单场记录需二次确认，并原子删除其转写、反馈和内容快照；不设回收站。
- 历史页只包含倒序列表、单场详情、反馈重试和单场删除。MVP 不做搜索、筛选、导出、标签、批量删除或趋势分析。

## Comments

历史数据的单一真相是会话创建后持续写入的 SQLite 记录，不是实时供应商会话或当前项目文档。
