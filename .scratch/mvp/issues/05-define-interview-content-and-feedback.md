# 定义面试内容、追问原则与反馈标尺

Type: grilling
Status: resolved
Blocked by:

## Question

候选人画像和“Node.js 全栈 + AI Agent”面试说明应如何组织，才能让 AI 面试官在固定 45 分钟内稳定地做到简历驱动追问、覆盖关键能力、不中途教学，并给出一致且可执行的会后反馈？

## Answer

已将内容分成两个独立、可版本化的项目资料：

- [候选人画像](../../../docs/product/candidate-profile.md) 只记录与面试有关的能力陈述、工作经历、可验证声明和优先追问，不保存联系方式等无关隐私。
- [Node.js 全栈 + AI Agent 面试说明](../../../docs/product/interview-brief.md) 定义 45 分钟时间预算、考察范围、追问原则、六维反馈标尺和回答复盘结构。

关键决策：

- MVP 固定为 45 分钟，取消 15/30/45 时长选择。一般技术面试需要足够时间完成自我介绍、项目深挖和岗位能力验证。
- 不包含代码编辑器、屏幕共享或现场 Coding 页面；只通过语音口述伪代码、接口、数据流、复杂度和异常处理。
- 时间预算为 5 分钟定位、15 分钟项目深挖、12 分钟 Node.js/全栈、10 分钟 AI Agent 和 3 分钟综合收尾，允许根据证据动态调整。
- 简历是待验证陈述，不是已证实事实；矛盾必须追问，不替候选人补全经历。
- 未获得足够证据的能力标记“本场未充分验证”，不等同于低分。
- 反馈提供六维 1–5 级评价和回答证据，不输出录用结论；另选取 3 个优秀片段、3 个改进片段和 3 个优先练习项。

## Comments

本票解决的是面试内容结构与评价规则，不建设固定题库。AI 面试官需在这些约束内根据实时回答动态选择下一个问题。
