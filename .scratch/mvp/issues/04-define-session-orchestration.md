# 定义实时面试的会话状态与异常恢复

Type: grilling
Status: resolved
Blocked by: 02, 03

## Question

一场面试从准备、开场、倾听、追问、双向打断到结束和反馈的状态转移应如何定义，权限被拒、网络中断、模型超时或转写不完整时如何恢复？

## Answer

### 主流程

1. **准备**：候选人进入固定 45 分钟的面试，授权麦克风和摄像头。两种设备都是必需；权限或实际输入任一缺失时不能开始。
2. **连接**：建立实时会话。连接完成后才创建进行中的历史记录并开始计时。
3. **面试**：AI 面试官在“说话”、“倾听”和“思考”间循环。候选人开口可打断 AI；AI 也可根据面试策略礼貌打断过长或偏题回答。手动“结束回答”作为语音活动检测的降级入口。
4. **收尾**：进行到 40 分 30 秒后，AI 不再开启新主题。45 分钟后完成当前回答并自然收尾，最晚在 47 分钟强制结束。
5. **反馈**：至少完成一轮候选人回答的正常收尾或手动结束都生成会后反馈，并将会话标记为“已完成”。

### 故障与恢复

- **实时连接断开**：立即暂停计时和对话，自动重连最多 20 秒。恢复后从最后一条已确认转写继续，不重复已确认的问题。20 秒仍失败则标记“已中断”，保存已有转写，不生成正式会后反馈。
- **AI 超时或语音失败**：等待超过 8 秒显示重连提示；15 秒时暂停计时并自动重试一次。再次失败后进入“面试已暂停”，用户可再次重试，或结束并基于已有内容生成反馈。
- **转写不完整**：历史只保存最终转写，不保存临时字幕。结束时最多等待 5 秒收齐尾部转写；仍缺失的片段标记为“转写缺失”，不猜补。可继续生成反馈，但需标注评价可能不完整。历史转写不可编辑。
- **提前退出**：第一轮候选人回答完成前退出则标记“已取消”，保存基本记录但不生成反馈。

## Comments

字幕是实时反馈，历史中的转写是最终记录；两者不应使用同一个可编辑文本概念。
