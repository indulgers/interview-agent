# 模拟面试交互与视觉改版设计

## 1. 背景与目标

现有 MVP 已能完成实时语音面试、保存转写并生成反馈，但交互和视觉仍像工程验证页面：控件反馈生硬、结束弹窗不会可靠退出、结束后滞留在房间、页面缺少稳定导航，且语义 VAD 会把候选人的自然停顿误判为回答结束。当前 SVG 面试官也削弱了真实面试感。

本轮改版把产品重塑为一间柔和、专业、可信的在线视频面试室。它不增加账号、题库、录屏、屏幕共享、代码编辑器或复杂数字人服务，只改善现有核心流程。

成功标准：

1. 页面具有统一、圆润、轻盈的交互语言，按钮、弹窗、切页和加载状态均有明确反馈。
2. 候选人只有点击“回答完成”才把当前轮次交给面试官，停顿不会触发追问。
3. 正常或提前结束都会立刻离开房间，进入本场总结，不出现无处可去的终态。
4. 用户始终能前往首页、模拟面试和面试记录。
5. 固定真人面试官素材能以低成本状态动画呈现聆听、思考与说话，不依赖数字人 API。

## 2. 设计方向

采用方案 A：“柔和专业的真实视频会议室”。

### 2.1 视觉语言

- 主背景：雾灰 `#F4F7F7`。
- 主表面：白色 `#FFFFFF`。
- 主文字：墨灰 `#18202A`。
- 品牌色：深鼠尾草绿 `#2F6656`。
- 次级绿色：柔和鼠尾草 `#6CA28F`。
- 危险色：克制砖红 `#A44D48`。

中文正文使用系统无衬线字体栈，标题使用较紧凑的现代无衬线字重，不再使用宋体大标题或报刊式细线布局。卡片采用 18–24px 圆角；按钮采用 12–14px 圆角；仅关键浮层使用柔和阴影。

动效集中在三处：页面内容淡入、按钮按压/悬停、真人面试官状态交叉淡入。所有动效控制在约 140–240ms，并尊重 `prefers-reduced-motion`。

### 2.2 全局导航

首页、面试房间之外的页面使用统一顶部导航：

- 首页
- 模拟面试
- 面试记录

面试进行中保留简化导航，只允许安全返回入口；若用户尝试离开进行中的房间，复用结束确认流程，防止误退出。总结页提供“返回首页”“查看面试记录”“再练一场”三个明确出口。

## 3. 面试房间

桌面端由真人面试官主画面和右侧信息栏组成。主画面显示固定真人面试官及当前字幕；右侧依次显示候选人本地视频、当前问题、当前轮次状态。移动端改为单列，候选人视频缩小但不遮挡字幕与主操作。

底部使用浮动控制栏：

- 麦克风开关。
- 摄像头开关。
- 高优先级“回答完成”。
- 低优先级“提前结束”。

按钮具有 hover、pressed、focus、disabled 和 loading 状态。触屏按下时立即产生缩放/颜色反馈，异步操作期间禁止重复提交。

不把完整实时转写放进房间。当前问题与面试官最后一句话可以显示为字幕，避免候选人忘记问题，但不能形成可读稿式滚动面板。

## 4. 显式回答轮次

候选人回答采用应用控制的显式轮次边界：

1. 面试官提问结束后进入 `answering` 状态。
2. 麦克风继续采集，ASR 可以产生候选人最终转写，但候选人的短暂停顿或 VAD `speech_stopped` 不允许触发模型生成下一问。
3. 候选人点击“回答完成”后，按钮进入提交状态；应用提交当前输入音频边界，并显式请求面试官响应。
4. 提交成功后进入 `thinking`，随后进入 `speaking`。
5. 面试官说话时麦克风仍开启。候选人开口可取消当前 AI 响应并重新进入 `answering`，保留现有 barge-in 能力。

连续较长时间未检测到任何候选人语音时，页面只显示“可以慢慢组织，完成后点击回答完成”的轻提示，不让面试官自动开口。提示不改变会话状态。

供应商配置需要关闭自动创建响应的 VAD 行为，同时保留服务端语音起止检测与转写。如果百炼 Realtime 无法可靠分离“检测语音结束”和“自动生成响应”，则通过 data channel 的显式事件或供应商支持的手动响应模式完成；不得用任意静音时长模拟用户点击。

## 5. 结束与总结流程

### 5.1 确认弹窗

点击“提前结束”打开居中模态框，背景使用半透明遮罩和轻微模糊。弹窗说明“已完成内容会保存并生成总结”。它必须支持：

- “继续面试”关闭弹窗并恢复焦点。
- Escape 关闭弹窗。
- 点击“确认结束”后立即进入 loading，禁止重复点击。
- 结束成功时先关闭弹窗，再执行页面跳转。
- 结束失败时保留可恢复提示与重试入口，不能永久覆盖房间控件。

### 5.2 跳转与总结

正常到时或提前结束都跳转到该场 `/history/[id]`。会话结束接口必须把可导航的 session ID 暴露给页面；页面不能只依赖本地 `finished` 状态。

总结页分两阶段：

1. 反馈生成中：立即显示已保存时长、回答轮数与柔和分析进度，允许用户离开；后台反馈状态可以安全刷新。
2. 反馈完成：原地呈现六维评价、面试官观察、证据片段和优先练习建议。

提前结束且至少存在一轮候选人最终回答时，结果为已完成并生成反馈。第一轮候选人回答之前结束时，仍保存记录并显示简要总结，但不生成正式六维评价，明确说明证据不足。

## 6. 真人面试官素材与动画

固定使用同一位中国男性技术面试官，约 35 岁，办公室视频会议构图。已确认的项目素材包括：

- `public/interviewer/base.png`
- `public/interviewer/listening.png`
- `public/interviewer/thinking.png`
- `public/interviewer/speaking.png`

运行时按会话状态切换：

- `listening` / `answering`：聆听图。
- `thinking` / `connecting`：思考图或基准图。
- `speaking`：说话图与基准图低频交替。
- `paused` / `closing` / `finished`：基准图。

状态变化用交叉淡入，容器使用幅度不超过约 1% 的缓慢呼吸位移。说话动画不是音素级口型同步，不宣称数字人能力。图片在接入前转换为浏览器友好格式并压缩；首屏只预加载当前状态，其他状态按需加载。加载失败回退到基准图，不阻塞语音面试。

## 7. 组件与状态边界

- `InterviewSession`：新增明确的回答轮次状态/命令，负责“回答完成”后才请求 AI 响应；继续负责打断、重连和持久化。
- `RealtimeVoice`：将“提交候选人输入”和“请求 AI 响应”建模为明确能力，百炼细节留在适配器内部。
- `InterviewExperience`：负责设备门、开始流程以及终态路由跳转，不自行推断 session ID。
- `InterviewRoom`：只渲染房间视图和派发用户意图；结束确认由独立可测试模态组件管理。
- `InterviewerPortrait`：根据会话状态选择真人素材，封装预加载、交叉淡入、降级和 reduced-motion。
- 历史详情页：成为会后总结的唯一页面，处理反馈生成、失败重试和导航。

全局 UI 原语保持项目内轻量实现，吸收 shadcn 的可访问性、圆角、动效和状态反馈，不为少量控件引入完整组件系统。如果现有依赖已包含合适的无障碍 Dialog primitive，可复用；否则实现聚焦的小型 Dialog，并覆盖焦点管理测试。

## 8. 错误与恢复

- 回答提交失败：恢复“回答完成”按钮并显示可重试提示，不丢弃已产生的最终转写。
- 结束保存失败：关闭 loading，保留房间与重试能力，不进行假跳转。
- 反馈生成失败：总结页保留已保存数据并提供“重新生成反馈”。
- 图片加载失败：使用基准图；全部失败时显示中性占位，不影响语音。
- 跳转失败或刷新：历史记录仍是事实来源，用户可从面试记录恢复到本场总结。
- 连接中断时不允许“回答完成”触发新响应；恢复后保持当前未提交回答的状态。

## 9. 测试与验收

### 9.1 自动化

- 状态机测试：候选人停顿和 `speech_stopped` 不触发下一问；只有显式“回答完成”才请求 AI 响应；连续点击幂等；说话时打断仍生效。
- 适配器测试：自动响应关闭；提交输入与请求响应事件顺序正确；断线时拒绝命令并可重试。
- 组件测试：弹窗可取消、Escape 可关闭、确认 loading 防重入、成功关闭并跳转、失败可恢复。
- 路由测试：提前结束返回 session ID；有回答与无回答的反馈策略正确。
- 页面测试：生成中、生成成功、生成失败三种总结状态都有出口。
- 可访问性：键盘焦点、可见 focus、Dialog 标签、reduced-motion。
- Playwright：完整执行“开始 → 自然停顿不追问 → 回答完成 → AI 下一问 → 提前结束 → 总结生成 → 返回历史”。

### 9.2 人工视觉验收

- 1440px、768px 和 390px 下无主要内容遮挡。
- 关键按钮按下即有反馈；弹窗无卡死或残留遮罩。
- 真人素材切换没有明显换脸、闪白或布局抖动。
- 正常网络下结束后 1 秒内离开房间并看见总结生成状态。
- 四张原图不直接作为未压缩生产资源交付。

## 10. 范围边界

本轮不做多面试官选择、精确唇形同步、视频生成、数字人服务、录制真人视频、背景替换、用户头像、主题切换、通知系统、趋势图或新题库。

本设计覆盖并替代原 MVP 设计中“数字人使用 SVG 闭嘴/张嘴两帧”“静音帮助 VAD 自动断句”和“照片级真人明确不做”的相关部分；其余产品范围继续有效。
