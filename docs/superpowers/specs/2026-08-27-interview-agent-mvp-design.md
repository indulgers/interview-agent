# AI 模拟面试 Agent MVP 设计

## 1. 目标

构建一个在中国大陆本机运行的单用户 Web 应用，帮助候选人进行 45 分钟“Node.js 全栈 + AI Agent”中文模拟面试。AI 面试官使用固定候选人画像从真实项目陈述出发，通过实时语音追问验证技术能力，并在结束后保存转写与生成结构化反馈。

产品只用于训练，不在真实面试过程中提供回答辅助。

## 2. MVP 成功标准

候选人能够在最新稳定版 Chrome 中：

1. 打开本机应用，通过麦克风和摄像头检测。
2. 开始固定 45 分钟的中文模拟面试。
3. 与会张嘴说话的轻量 AI 数字面试官进行低延迟语音交流。
4. 在 AI 发言时开口打断，并在自动断句失效时使用“结束回答”。
5. 经历项目深挖、Node.js/全栈、AI Agent 和工程取舍的自适应追问。
6. 在结束后查看双方最终转写、六维反馈和优先练习项。
7. 在后续打开应用时从本地历史中回看该场记录。

## 3. 用户与范围

### 3.1 用户

MVP 只有一个本地候选人，不做登录、注册、多用户、权限、订阅或付费。

### 3.2 固定内容

- 候选人画像来自用户指定的简历，但只保留技术能力和项目经历，不保留姓名、电话、邮箱、出生日期和住址。
- 面试说明固定为“Node.js 全栈 + AI Agent”，按 1–3 年经验、能够独立交付业务功能的标尺追问。
- MVP 不做简历上传、题库、课程、面试方向选择或内容管理。

### 3.3 明确不做

- 真实面试辅助。
- 代码编辑器、屏幕共享或现场 Coding 页面。
- 候选人视频上传、录像、表情、眼神或肢体分析。
- 音频和视频历史回放。
- 3D 数字人、照片级真人或精确音素唇形。
- 实时转写为主视图的面试工作台。
- 搜索、筛选、导出、标签、批量删除、回收站和多场趋势分析。
- 公网部署和云数据库。

## 4. 产品流程

### 4.1 首页与设备就绪

首页显示产品目的、固定面试方向、45 分钟时长和历史入口。开始前请求麦克风与摄像头权限，并同时检查两种设备是否实际产生输入。

两种设备都是必需。任一设备未授权、不存在或无输入时，“开始面试”不可用，页面显示可执行的修复提示。

### 4.2 面试房间

采用“沉浸式面试官”布局：

- AI 面试官占据中央主舞台。
- 候选人摄像头是右上角画中画，并明示“仅本地预览”。
- 当前问题、AI 的倾听/思考/说话状态和打断提示以轻量覆盖层显示。
- 底部提供麦克风、摄像头、“结束回答”和“结束面试”控件。
- 面试进行中不展示完整实时转写，避免候选人读稿。

数字人使用固定头像、闭嘴/张嘴两帧和远端音轨音量驱动。AI 停止播放时恢复闭嘴。

### 4.3 面试内容

时间预算：

- 0–5 分钟：自我介绍与经历定位。
- 5–20 分钟：代表项目的职责、难点、取舍和结果深挖。
- 20–32 分钟：Node.js 后端与全栈工程能力。
- 32–42 分钟：AI Agent、上下文管理、Tool Calling、RAG、评估和失败恢复。
- 42–45 分钟：综合场景追问与自然收尾。

时间段是引导预算，AI 可根据证据调整。面试从简历中的候选人陈述出发，但将其视为待验证声明：对职责边界、具体方案、技术取舍、故障案例和结果指标追问。如果回答与简历矛盾，AI 指出矛盾并追问，不替候选人补全。

面试中不教学、不提示答案、不报分。可要求口述伪代码、接口、数据流、复杂度和异常处理。

### 4.4 收尾与反馈

40 分 30 秒后不再开启新主题；45 分钟后完成当前回答并自然收尾，最晚 47 分钟强制结束。会后反馈在对话结束后生成，不占 45 分钟面试时间。

反馈使用六维 1–5 级评价：

1. 项目真实性与个人贡献。
2. Node.js 后端能力。
3. 前端与全栈交付能力。
4. AI Agent 应用能力。
5. 系统设计与工程取舍。
6. 表达结构与追问应对。

每个维度必须引用本场证据，给出优点、问题和下一步练习建议。证据不足时标记“本场未充分验证”，不直接判低分。另选取 3 个最好片段、3 个改进片段和 3 个优先练习项。不输出“建议录用 / 不建议录用”。

## 5. 会话状态与恢复

### 5.1 主状态

会话在准备、连接、进行中、暂停、收尾和终态之间迁移。进行中的可视子状态是 AI 倾听、思考和说话。

终态是：

- **已完成**：正常收尾，或至少完成一轮候选人回答后手动结束。
- **已中断**：连接或服务故障后无法恢复。
- **已取消**：第一轮候选人回答完成前主动退出。

已完成会话生成反馈。已中断和已取消保存可用历史，但不生成正式反馈。

### 5.2 双向打断

候选人在 AI 发言时开口，系统停止未播放语音并转入倾听。AI 可对过长、空泛或偏题回答礼貌打断。VAD 不可用时，候选人使用“结束回答”手动提交。

### 5.3 连接中断

立即暂停计时和对话，自动重连最多 20 秒。恢复后从最后已确认转写继续，不重复已确认问题。20 秒未恢复则标记已中断，保存已有转写。

### 5.4 AI 超时或语音失败

8 秒无响应显示重连提示；15 秒时暂停计时并自动重试一次。再次失败后进入暂停，用户可再次重试，或结束并基于已有内容生成反馈。

### 5.5 转写缺失

历史只保存最终转写。结束时最多等待 5 秒收齐尾部转写；仍缺失的片段标记“转写缺失”，不猜补。反馈中标注评价可能不完整。转写不可编辑。

## 6. 历史与数据

### 6.1 持久化时机

WebRTC 连接成功后创建“进行中”会话与内容快照。候选人或 AI 的每轮最终转写确认后，立即以幂等方式追加到 SQLite。应用启动时发现遗留的“进行中”记录，将其收敛为“已中断”。

### 6.2 内容快照

每场保存当时候选人画像和面试说明的完整不可变快照，以及人类可读版本标识和内容哈希。历史回看和反馈重试只使用该场快照，不读取后来修改的项目文档。

### 6.3 反馈状态

反馈状态与会话结果分开：待生成、生成中、已完成、生成失败、不适用。生成失败不回滚已完成会话；历史页允许使用原转写和快照重试。

### 6.4 历史页

历史列表按开始时间倒序排列，显示会话结果、实际时长、反馈状态和转写完整性。详情页显示双方完整转写、六维反馈和本场内容版本。

记录默认永久保留。用户可二次确认后删除单场，在一个事务中同时删除会话、转写、快照和反馈，不设回收站。

## 7. 技术架构

### 7.1 运行形态

采用 Next.js App Router + React + TypeScript 单体应用，使用 pnpm 和单一开发启动命令。页面与本机 Node.js 接口在同一项目和进程中。

其他技术：

- Tailwind CSS。
- Drizzle ORM + SQLite。
- Zod。
- Vitest + Playwright。

不拆成 React/Vite + Fastify 双进程，不打包 Electron。

### 7.2 实时语音

主路径是阿里云百炼 `Qwen3.5-Omni-Flash-Realtime`（华北 2 北京）+ 浏览器 WebRTC。

1. 浏览器创建 WebRTC Offer。
2. 本机 Node.js 读取 `DASHSCOPE_API_KEY`，向百炼代理 SDP 交换。
3. 浏览器获得 SDP Answer，与百炼直接传输音频与事件。
4. 长期 Key 不进入浏览器、SQLite 或日志。

曾经在对话中发送的 Key 视为已泄露，必须撤销。实现只能使用轮换后存放在本机环境变量的新 Key。

### 7.3 深模块

- `InterviewSession`：设备就绪、会话状态、计时、打断、重连、收尾和结果的唯一入口。
- `RealtimeVoice`：隐藏供应商、WebRTC、SDP、data channel 事件与播放细节。提供百炼生产适配器和可编程内存测试适配器。
- `InterviewContent`：从固定资料生成快照、版本/哈希和实时会话指令。
- `InterviewHistory`：会话、最终转写、快照、反馈状态和删除的唯一持久化入口。
- `InterviewFeedback`：使用已保存转写与快照生成和校验结构化反馈。

SQLite 测试直接使用临时数据库，不为唯一生产实现造额外 Repository seam。

### 7.4 降级路径

在 `RealtimeVoice` seam 后保留同厂商的流式 ASR → Qwen 文本模型 → 流式 TTS 适配器路线。MVP 先实现端到端百炼 Realtime；只有真实 PoC 整体未达标时才实现组合链路。VAD 单项未达标时，优先使用已确认的手动“结束回答”降级，不立即更换整个语音链路。

## 8. 错误处理与安全

- 百炼事件先经 Zod 校验并转换为内部标准事件。未知事件记录但不直接中止会话。
- 供应商错误映射为可自动重试、需用户重试、配置错误、连接中断或不可恢复。
- 用户界面不显示原始供应商载荷、密钥、栈跟踪或敏感配置。
- 每轮转写使用稳定标识与会话内递增序号幂等写入，重连事件不产生重复历史。
- 会话结果只能从进行中迁移到一个终态。
- 删除单场历史在 SQLite 事务中级联完成。

## 9. 验证计划

### 9.1 自动化验证

- `InterviewSession`：假时钟 + 内存语音适配器，覆盖 45 分钟流程、打断、超时、重连、软收尾和终态。
- `InterviewContent`：快照、版本/哈希、指令组装和隐私过滤。
- `InterviewHistory`：临时 SQLite 中的逐轮写入、幂等、崩溃收敛、快照、反馈重试和删除事务。
- `InterviewFeedback`：固定模型适配器下的六维结构、未充分验证、转写缺失警告和快照重试。
- `RealtimeVoice`：使用阿里云官方文档的固定事件样本验证事件转换契约。
- Playwright：使用内存语音适配器覆盖设备检查、开始、转写入库、结束、反馈和历史回看。

### 9.2 真实网络 PoC

使用轮换后的新 Key，在中国大陆真实网络中完成一轮 50 分钟端到端测试，同时验证：

- 单连接或续接后的 50 分钟运行。
- Node.js、TypeScript、NestJS、WebSocket、RAG、Tool Calling、MCP 等中英技术词的最终转写。
- 扬声器回声下候选人打断 AI。
- 5–15 秒断网后的连接恢复和已保存转写不丢失。
- 首音延迟、打断停止延迟和控制台实际单场费用。

工程目标是打断停止主观感受不超过约 500 ms，普通轮次首个可听响应以 1.5 s 为目标。这些不是供应商 SLA，真实验收以 PoC 结果和用户主观可接受性为准。

## 10. 实现顺序约束

实现计划必须按下列风险顺序组织：

1. 用最小界面完成百炼 WebRTC 建连、双向语音、打断和双方转写 spike。
2. 完成一轮 50 分钟真实网络 PoC，决定保留端到端 Realtime，还是实现组合链路适配器。
3. 使用 TDD 实现会话状态与深模块接口。
4. 实现历史持久化和反馈生成。
5. 按已选原型实现面试房间、首页和历史页。
6. 完成自动化测试、真实流程验证和 Spec/Standards 双轴 Review。
