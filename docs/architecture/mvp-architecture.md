# AI 模拟面试 MVP 架构

## 架构目标

以一个本机运行、单用户的 Next.js 应用完成 45 分钟中文实时语音模拟面试。架构必须优先保证自然语音对话、双向打断、逐轮历史保存和会后反馈，不为不在 MVP 中的多用户、云部署或代码面试预留复杂基础设施。

## 技术栈

- **应用骨架**：Next.js App Router + React + TypeScript。
- **样式**：Tailwind CSS，依照已确认的“沉浸式面试官”原型重新实现生产界面。
- **实时语音**：阿里云百炼 `Qwen3.5-Omni-Flash-Realtime`（华北 2 北京），浏览器 WebRTC。
- **数据**：SQLite + Drizzle ORM；本机 Node.js 运行时使用 SQLite 驱动，不运行在 Edge runtime。
- **数据校验**：Zod，用于应用输入、持久化边界与百炼事件解析。
- **测试**：Vitest + Playwright。
- **包管理与任务**：pnpm，项目必须提供单一开发启动命令。

版本号在实现计划和项目脚手架阶段根据当时官方稳定版确定，本架构不将时效性强的版本号当作产品决策。

## 运行形态

应用只有一个 Next.js/Node.js 进程和一个浏览器客户端。

- 浏览器负责设备检查、本地摄像头预览、WebRTC 媒体、远端音频播放、数字人嘴型动画和当前页面状态。
- Node.js 负责百炼 SDP 鉴权代理、内容快照、会话和转写持久化、反馈生成和历史查询。
- 实时音频通过 WebRTC 在浏览器和百炼之间传输，不经过本机 Node.js 音频中继。
- 长期 `DASHSCOPE_API_KEY` 只存在本机服务端环境变量，不返回浏览器、不进入数据库、不写入日志。用户曾在对话中发送的 Key 视为已泄露，实现只能使用轮换后的新 Key。

## 深模块与接口

### InterviewSession

会话编排的唯一入口。调用方只提交业务命令和外部事件，读取当前会话视图；不理解百炼事件、数据库表或计时器实现。

负责：

- 麦克风与摄像头就绪条件。
- 连接、开场、倾听、思考、说话、暂停、重连、收尾和结束状态。
- 45 分钟时间预算、40 分 30 秒停止新主题、47 分钟硬上限。
- 双向打断、超时恢复、会话结果和反馈启动条件。

时钟是注入依赖，使状态机可以使用假时钟确定性测试。

### RealtimeVoice

隐藏实时语音供应商、WebRTC 建连、SDP、data channel 事件和远端音频播放细节。

对外接口只表达：连接、提交或结束候选人回答、取消 AI 发言、断开，以及订阅标准化的连接/说话/转写/错误事件。

这是真正的外部 seam：

- 生产适配器：百炼 Qwen3.5 Omni Realtime。
- 测试适配器：可编程内存语音适配器，用于发送确定性的转写、打断和断线事件。

若端到端方案在 PoC 中未达标，在同一 seam 后新增阿里云 ASR → Qwen 文本 → TTS 适配器，不改变会话和页面。

### InterviewContent

从项目内候选人画像和面试说明生成一场会话的不可变内容快照与实时会话指令。

它是进程内纯模块：对外返回完整快照、版本/哈希和组装后的面试指令，不暴露文件路径或提示词拼接步骤。

### InterviewHistory

历史数据的唯一真相和唯一写入入口。

对外接口表达业务动作：开始会话、追加最终转写、完成/中断/取消会话、更新反馈状态、查看列表/详情和删除单场。

SQLite 是本地可替代依赖；测试直接使用临时 SQLite 数据库跨该模块接口验证，不为唯一生产实现额外造一层“Repository 接口”。

### InterviewFeedback

从一场已完成会话的转写和内容快照生成结构化六维反馈。

外部模型调用位于内部 seam：

- 生产适配器：百炼文本模型。
- 测试适配器：返回固定合法反馈的内存适配器。

模块负责校验模型输出、写入反馈状态和保证重试仍使用原始快照。

## 主数据流

1. 浏览器完成麦克风和摄像头检测。
2. `InterviewContent` 生成本场内容快照和会话指令。
3. Node.js 读取环境变量中的新 Key，向百炼转发 WebRTC SDP 建连请求；浏览器只接收 SDP Answer。
4. WebRTC 连接成功后，`InterviewSession` 通过 `InterviewHistory` 创建“进行中”会话和内容快照，然后开始计时。
5. `RealtimeVoice` 将百炼事件校验并标准化。`InterviewSession` 消费这些事件，每收到一轮最终转写就立即、幂等地追加到 `InterviewHistory`。
6. 收尾时最多等待 5 秒收集尾部转写，写入会话结果和转写完整性。
7. 已完成且至少有一轮候选人回答时，`InterviewFeedback` 读取该场已保存的转写和快照，生成反馈并写回 `InterviewHistory`。
8. 历史页只读取 SQLite，不重新读取当前内容文档，也不依赖百炼实时会话。

## 错误分类

百炼事件在进入业务模块前经 Zod 校验。未知事件记录诊断信息并忽略，不直接破坏会话。供应商错误统一映射成：

- 可自动重试。
- 需要用户重试。
- 权限或本机配置错误。
- 连接中断。
- 不可恢复。

错误对用户显示可执行的恢复方式，不显示原始供应商载荷、密钥或栈信息。

## 幂等与一致性

- 每个转写轮次在会话内使用稳定标识和严格递增序号；重连后的重复事件不会产生重复历史。
- 会话结果只允许从“进行中”迁移到一个终态。
- 反馈状态与会话结果分离，反馈失败不回滚已完成的会话。
- 删除单场会话及其转写、快照和反馈在一个 SQLite 事务中完成。

## 验证策略

### 模块接口测试

- `InterviewSession`：使用假时钟、内存语音适配器和内存历史观察器，验证设备就绪、45 分钟流程、双向打断、超时、重连、软收尾和终态。
- `InterviewContent`：验证快照、版本/哈希、指令组装和不含联系方式等无关隐私。
- `InterviewHistory`：使用临时 SQLite 验证逐轮写入、幂等、崩溃收敛、内容快照、反馈重试和删除事务。
- `InterviewFeedback`：使用固定反馈适配器验证结构化输出、“未充分验证”、转写缺失警告和重试使用原快照。

### 适配器与完整流程

- 使用来自阿里云官方文档的固定事件样本做百炼适配器契约测试。
- Playwright 使用可编程内存语音适配器，验证从设备检查、开始面试、转写入库、结束、反馈到历史回看的完整流程。
- 使用轮换后的真实 Key 在国内网络完成一轮 50 分钟 PoC，同时验证长连接/断线续接、中英技术词最终转写、首音延迟、打断停止延迟和单场费用。

PoC 是实现计划中的前置 spike。若 VAD 未达标，启用已确认的手动“结束回答”降级；若端到端语音整体未达标，再实现同厂商组合链路适配器。

## 未选方案

### React/Vite + Fastify 分离

模块分开部署的价值小于两个开发进程、跨域、两套构建和额外类型分发带来的成本。本机单用户 MVP 不需要该拆分。

### Electron 桌面应用

桌面打包、媒体权限、升级和发布复杂度不服务当前本机 Web 目标，因此不纳入 MVP。
